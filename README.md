# northpulsar.com

Source for the live site, including the two pages App Store Connect
requires: a public support page and a public privacy policy.

| Path | Serves |
| --- | --- |
| `/` | Brand landing page for NorthPulsar |
| `/app` | Support URL given to Apple. Contact, common questions, how to erase your data |
| `/app/privacy` | Privacy Policy URL given to Apple |

## How it is built

Every page is generated by `src/build.py`, which inlines `src/_shared.css`
and `src/_mark.svg` into each one. The result is a set of self-contained
files: no external stylesheet, no web fonts, no scripts, no CDN. They render
identically from any host and can be opened straight from disk.

Build locally with:

```
python3 src/build.py
```

Output lands in `site/`, which is deliberately not committed. CI rebuilds it
on every deploy, so `src/` is the single source of truth and the two can
never drift.

## How publishing works

Push to `main`. The `Deploy northpulsar.com` GitHub Action builds `site/` and
uploads it over FTPS to the Namecheap shared host.

The action runs with `dangerous-clean-slate: false`, so it only adds and
updates files. It never deletes anything that exists on the server but not in
this repo. That is deliberate: `/.well-known/pki-validation` holds the SSL
validation file and deleting it would break certificate renewal. The flip
side is that removing a file here does not remove it from the server; delete
those by hand in cPanel File Manager.

## Required repository secrets

| Secret | Value |
| --- | --- |
| `FTP_SERVER` | `premium161.web-hosting.com` |
| `FTP_USERNAME` | the full FTP username, including the `@domain` part |
| `FTP_PASSWORD` | that FTP account's password |

The FTP account must be scoped to this site's document root,
`/home/<account>/northpulsar.com`, which is why `server-dir` is `/` rather
than a path. An account whose home is elsewhere will publish into the wrong
place and the deploy will still report success.

Use a dedicated FTP account for this domain rather than the one that
publishes the other sites on the same plan. If the secret ever leaks, the
blast radius is one static site.

## Testing a change safely

Run the workflow manually from the Actions tab and set the `target` input to
something like `/_deploytest/`. That publishes a full copy into a throwaway
directory without touching the live site.
